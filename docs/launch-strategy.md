# 한쪽 런칭 — 반응 측정 전략

- 날짜: 2026-09-02
- 목적: 로드맵 **2단계 "수요 검증"**(4~6주)의 실행 계획. 수익이 아니라 *"나 말고 원하는 사람이 있나"*를 싸게 확인한다.
- 판정 결과가 3단계(iCloud 동기화 + iOS + 영문 로컬라이즈) 투자 여부를 결정한다.

## 0. 전제 — 이 앱에서 "반응"은 어디서 읽히나

**앱 안에서는 아무것도 재지 않는다.** 네트워크·텔레메트리 없음은 스펙의 확정 정책이고, App Store 개인정보 라벨 "수집 안 함"은 심사와 신뢰 양쪽의 자산이다. 런칭 반응을 보겠다고 이 원칙을 깨면 얻는 것보다 잃는 게 크다.

따라서 계기판은 전부 **앱 바깥**에 있다:

| 신호 | 출처 | 코드 변경 | 무엇을 말해주나 |
|---|---|---|---|
| 노출 → 페이지 조회 → 다운로드 | App Store Connect 앱 분석 | 0줄 | 퍼널 전환율. 스크린샷·설명이 먹히는지 |
| 유입 소스별 다운로드 | 앱 분석 → 소스 → **캠페인** | 0줄 | **어느 커뮤니티가 실제 다운로드를 만드는지** (§2-2 캠페인 링크 전제) |
| D1 / D7 / D28 유지율 | 앱 분석 (옵트인 기기 표본) | 0줄 | 깔고 나서 계속 쓰는지. 표본은 작지만 방향은 읽힌다 |
| 리뷰 수·평점·본문 | App Store | 0줄 | 가장 정직한 정성 신호. 단, 다운로드의 1~2%만 남긴다 |
| 피드백 메일·폼 | 앱 메뉴 "피드백 보내기" | ~30분 | 리뷰보다 구체적인 요청·버그. **런칭 전 필수** (§2-1) |
| 업보트·댓글·북마크·리트윗 | 각 커뮤니티 | 0줄 | 관심의 크기와 *어떤 문장이* 반응을 만드는지 |
| 반복 요청 Top 3 | 위 전부를 태깅 집계 | 시트 1장 | 3단계 우선순위의 근거 |

App Store 분석에서 "검색어" 자체는 보이지 않는다(소스 종류까지만). 검색 유입 비중이 크면 그건 키워드가 잡혔다는 뜻이다.

## 1. 무기와 약점을 먼저 인정한다

- **무기 1 — 초성 검색.** `ㅅㅇㄷ`로 찾고 `사이ㄷ` 조합 중에도 결과가 안 끊긴다. 외산 앱은 만들지 않는다. **모든 채널에서 첫 문장은 이것.**
- **무기 2 — 한지 비주얼.** 라이트=한지·다크=먹. 글로는 안 퍼지고 **GIF로 퍼진다.** 이미지 없는 포스트는 하지 않는다.
- **무기 3 — 카톡 "나와의 채팅" 대체**라는 한 줄 설명. 설명이 한 문장에 끝나는 제품은 공유가 쉽다.
- **약점 — 한국어 UI만.** 영어권 채널(r/macapps, Show HN, Product Hunt)은 3단계 로컬라이즈 전엔 반응이 안 나온다. 억지로 가면 첫인상만 소모한다. **미룬다.**
- **약점 — 동기화·iOS 없음.** 요청이 올 것이다. 그 요청의 *양*이 바로 3단계 GO 신호이므로, 없다는 사실을 숨기지 말고 "요청 많으면 만든다"고 공개적으로 말한다. 그러면 요청이 측정 가능한 형태로 모인다.

## 2. 런칭 전 준비 (1~2일)

### 2-1. 피드백 통로 — 유일한 코드 변경
메뉴바 우클릭 메뉴와 설정 창에 **"피드백 보내기…"** 항목. `NSWorkspace.shared.open(mailto: 또는 폼 URL)`로 브라우저·메일 앱에 넘긴다. 앱이 데이터를 수집하는 게 아니라 사용자가 직접 보내는 것이므로 개인정보 라벨은 그대로 "수집 안 함"이다. 샌드박스에서도 URL 열기는 허용된다.

메일이 폼보다 낫다 — 답장이 가능하고, 답장한 사용자가 리뷰를 남긴다.

### 2-2. 채널별 캠페인 링크
App Store Connect → 앱 분석 → 소스 → 캠페인에서 링크를 만든다. 형식:

```
https://apps.apple.com/kr/app/id<앱ID>?pt=<provider>&ct=<채널토큰>&mt=8
```

채널 토큰은 하나씩: `disquiet` `openchat` `geeknews` `clien` `naver` `x` `threads` `blog`. **커뮤니티 포스트는 랜딩 페이지를 거치지 않고 이 링크로 App Store에 직행**시킨다. 랜딩을 거치면 전부 "웹 리퍼러 = hanjjok.app"으로 뭉쳐서 채널 구분이 사라진다.

### 2-3. 핵심 GIF 1개 (10초, 라이트·다크 2벌)
`⌥Space` → 패널이 오른쪽에서 슬라이드 → 메모 몇 장 보이는 상태에서 `ㅅㅇㄷ` 타이핑 → 결과가 글자마다 실시간으로 좁혀짐 → 조합 중(`사이ㄷ`)에도 안 끊김. 이 10초가 전 채널 공용 자산이다. 스크린샷 4~5장(스토어·커뮤니티 공용)도 같은 세션에서 찍는다.

### 2-4. 한 줄 훅 3종 (채널마다 골라 쓴다)
- 사용자용: **"초성으로 찾는 맥 메모장."**
- 메이커용: **"카톡 '나와의 채팅'을 Mac 메뉴바로 옮겼다."**
- 기술용: **"한글 조합 중에도 안 끊기는 검색 — 자모 분해 인덱싱으로 푼 이야기."**

### 2-5. 랜딩 최소본 — `hanjjok.app`
한 화면: GIF + 훅 + App Store 버튼 + 개인정보처리방침 링크. 그 이상은 만들지 않는다. 랜딩은 사람이 URL을 직접 칠 때와 SEO용이지, 커뮤니티 유입 경로가 아니다(§2-2).

### 2-6. Apple Featuring Nomination
App Store Connect → Featuring → Nominations → **App Launch** 유형. 최소 2주 전, 권장 3개월 전이라 승인 직후 제출하면 기대치는 낮다. 그래도 낸다 — 7개 기준(UX·UI 디자인·혁신성·독창성·접근성·로컬라이즈·제품 페이지) 중 UI 디자인·독창성·혁신성은 이 앱의 강점이다. 로컬라이즈 약점은 3단계 후 **App Enhancements** 유형으로 재신청해 메운다.

## 3. 채널 순서 — 작은 데서 시작해 피드백 반영 후 큰 데로

원칙: **한 웨이브의 피드백을 반영한 뒤 다음 웨이브.** 첫인상은 채널마다 한 번뿐이다.

### Wave 0 — 승인일 (D0): 아무 데도 안 올린다
스토어 페이지·캠페인 링크·크래시 리포트 확인. 지인 5~10명에게 직접 링크 → **첫 리뷰 3~5개.** 리뷰 0인 상태로 커뮤니티에 노출되면 전환이 떨어진다. (지인 동원 *대량* 리뷰는 정책 위반이자 티가 난다 — 실제로 쓰는 몇 명만.)

### Wave 1 — D+1~3: 작은 곳, 피드백 밀도 우선
| 곳 | 형식 | 이유 |
|---|---|---|
| **디스콰이엇** | 프로덕트 등록 + 메이커로그 1편 | 메이커들이 진짜 피드백을 준다. 메이킹 스토리(카톡 → 초성 검색 → IME 지옥)가 먹힌다 |
| **카카오톡 오픈채팅** 1~2곳 (맥 사용자·생산성 앱) | GIF + 링크 + "의견 주세요" | 반응이 즉각적이고 솔직하다 |

→ 여기서 나온 버그·불만을 **3~5일 안에 1.0.1로 반영.** 이게 Wave 2의 전제 조건이다.

### Wave 2 — D+7~10: 본진
| 곳 | 형식 | 이유 |
|---|---|---|
| **GeekNews** (Show GN) | 기술 각도 글 — 자모 분해 인덱싱, LIKE vs FTS 선택 이유, `nonactivatingPanel`, 샌드박스에서 겪은 일 | 한국 개발자 중 Mac 밀도가 가장 높다. 기술 스토리에 반응한다 |
| **클리앙 맥 게시판** (cm_mac) | 사용자 관점 — "만들었습니다, 써보고 의견 주세요" 톤 + GIF | 직접 타깃. 광고성으로 읽히면 역효과 |
| **네이버 카페 맥쓰사** | 홍보 게시판 규정 확인 후 | 비개발자 Mac 사용자. 규모가 크다 |

### Wave 3 — D+10~14: 확산
| 곳 | 형식 | 이유 |
|---|---|---|
| **X · 스레드** | GIF 단독 포스트, 짧은 문장 | 한지 비주얼이 퍼지는 곳. 계정 태깅·과다 해시태그 금지 — 스팸으로 읽힌다 |
| **브런치 또는 벨로그** | 롱폼 "왜 만들었나 + 한지 디자인 과정" | 검색 롱테일. 요즘IT·서핏 큐레이션이 픽업할 수 있다 |

### Wave 4 — 3단계 이후 (영문 로컬라이즈 + 동기화·iOS 갖춘 뒤)
| 곳 | 조건 |
|---|---|
| r/macapps | 영문 UI 필수. self-promo 규칙 엄수 |
| Show HN | 기술 각도. 한국어 전용이면 반응 없음 |
| **Product Hunt** | **한 번뿐이다.** iOS·동기화 갖춘 1.x 또는 2.0에서. 지금 쓰면 낭비 |
| Setapp 입점 | 유료화 시점 |

## 4. 판정 기준 — D+42 (6주)

> 아래 숫자는 **잠정치**다. 한국 데스크톱 macOS 점유율 8.7%, 카테고리 리더(SideNotes)조차 스토어 리뷰 임계치를 못 넘는 니치라는 시장조사 결과에서 감으로 잡았다. **1주차 실측 후 조정한다.** 숫자보다 세 판정의 *구분*이 중요하다.

| 지표 | 🟢 3단계 GO | 🟡 제품부터 손본다 | 🔴 개인 도구로 유지 |
|---|---|---|---|
| 다운로드 누계 | ≥ 1,000 | 300~1,000 | < 200 (전 채널 소진 후) |
| D7 유지율 | ≥ 20% | < 15% | — |
| 리뷰 | ≥ 15개, 평점 ≥ 4.3 | 있으나 불만 반복 | < 5개 |
| 정성 | 동기화·iOS 요청이 피드백 상위권 | 첫 경험·온보딩 불만이 상위권 | 자발적 언급 0 |

- **🟢**: 사람들이 깔고, 계속 쓰고, 더 달라고 한다. 3단계에 투자한다.
- **🟡**: 깔지만 안 남는다. 첫 실행 경험의 문제다. 동기화·iOS를 얹기 전에 이걸 고쳐야 한다 — 새는 통에 물 붓지 않는다.
- **🔴**: 무리하지 않는다. 얻은 것은 포트폴리오와 매일 쓰는 본인용 도구이고, 그건 원래 스펙의 1차 목표였다.

## 5. 주간 리듬 (6주)

- **매주 월요일**: App Store 분석 스냅샷을 아래 표에 손으로 적는다. 자동화하지 않는다 — 숫자를 직접 보는 게 판단에 낫다.
- **피드백 태깅 시트** (구글 시트 또는 이 문서 하단): 날짜 / 채널 / 원문 / 태그(`sync` `ios` `en` `hotkey` `font` `bug` `onboarding` …) / 대응.
- **매주 메이커로그 1편** — 숫자를 공개한다. "이번 주 다운로드 N, 요청 1위 동기화." 빌드 인 퍼블릭은 그 자체가 유입이다.

## 6. 하지 말 것

- **여러 채널 동시 투하.** 피드백 반영 전에 큰 데 가면 첫인상을 버그와 함께 소모한다.
- **텔레메트리 추가.** 유혹이 올 것이다. 라벨 "수집 안 함"은 자산이다. 깨지 않는다.
- **광고 어투.** "출시했습니다!"가 아니라 "만들었는데 써보고 의견 주세요".
- **지인 대량 리뷰.** Apple 정책 위반이고, 커뮤니티는 알아본다.
- **Product Hunt 조기 소진.** 한 번뿐이다.
- **한국어 UI로 영어권 진입.** 3단계 전엔 가지 않는다.
- **판정일 전 조기 결론.** 1주차 숫자로 흥분하거나 낙담하지 않는다. 6주 채운다.
