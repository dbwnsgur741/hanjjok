# 갈피 (Galpi) — 설계 문서

- 날짜: 2026-08-31
- 상태: 사용자 검토 대기

## 1. 개요와 목표

macOS 화면 가장자리에서 슬라이드로 나타나는 한국형 빠른 메모 앱.
SideNotes(Apptorium)의 엣지 패널 인터랙션을 원형으로 하되, 한국 사용자의
메모 습관(카카오톡 나와의 채팅)과 미감(한지·붓·오방색)으로 재해석한다.

**목표**: 먼저 제작자 본인이 매일 쓰는 도구. 반응이 좋으면 출시로 확장.
**성공 기준**: 생각→기록까지 1초 이내. 본인이 카톡 나와의 채팅 대신 이 앱을 열게 되는 것.

리서치 근거: SideNotes 기능 분석 + 한국 메모 시장·문화 조사
(리포트: https://claude.ai/code/artifact/f509a9b2-de7c-46da-9717-be3b1a0131cc)

## 2. 포지셔닝

**카톡식 타임라인 스크래치패드.** 위→아래로 쌓이는 시간순 스트림 + 해시태그 분류.
폴더 없음. 보관은 가능하되 "흘러가는 기록"이 기본 멘탈 모델.

**[v1.1 개정]** 기본 화면은 전체 타임라인(빠른 캡처 정체성 유지), 여기에 **1단계 평면 폴더**를
필터 뷰로 얹는다. 폴더 = 메모의 소속(메모당 1개, 이동 가능, 미지정 시 "미분류"),
태그 = 편집 중 붙이는 가로 분류(여러 개) — 역할이 다르며 병행한다.
진입은 헤더의 서랍 드로어(폴더·태그 목록 + 메모 수).

**[v1.2 개정]** ① 폴더 1차 전환은 헤더 아래 **폴더 칩 바**(전체·폴더들·미분류)로 이동 —
항상 보이는 원클릭 전환. 드로어는 폴더 관리(CRUD)·태그 목록 담당으로 역할 축소.
② 스크래치패드 정체성에 **가벼운 할 일**을 얹는다: 본문에서 줄 앞에 `[] `를 치면
체크리스트 항목으로 렌더링되고 카드에서 클릭해 완료를 토글한다. 별도 투두 엔티티·화면
없음 — 메모 한 장이 곧 투두리스트가 된다.

이 카테고리 성공작의 공통점은 "무엇을 안 하는지"의 명확함이다. 갈피가 안 하는 것:

- 폴더 계층(폴더 안 폴더) — 1단계 평면까지만
- 제목 있는 문서형 노트
- ~~서식 도구 모음 (마크다운 문법도 없음)~~ → **[v1.3 개정]** 경량 마크다운 에디터로 전환.
  "순수 텍스트" 원칙은 *저장 형식*에만 남는다(본문은 여전히 평문 .md 텍스트).
  WYSIWYG·리치텍스트 저장·표·이미지 임베드는 여전히 제외.
- 계정·서버·텔레메트리

## 4. 아키텍처 — DDD-lite 레이어드

SPM 로컬 패키지로 레이어를 물리 분리. 의존 방향은 항상 안쪽(Domain)으로.
정통 DDD의 무거운 의식(Aggregate 경계, Domain Event, Bounded Context)은
채택하지 않는다 — 애그리거트가 사실상 `Note` 하나뿐이다.

```
side-notes/
├── Galpi.xcodeproj
├── Galpi/                   # App 타깃: SwiftUI 뷰, @Observable 뷰모델, 에셋
├── Packages/
│   ├── Domain/              # 순수 Swift. 프레임워크 import 금지
│   ├── Data/                # GRDB 구현체 (Domain의 Repository protocol 구현)
│   └── PanelKit/            # AppKit 격리: NSPanel, 글로벌 단축키, 메뉴바 아이콘
└── docs/superpowers/specs/
```

- App → Domain ← Data. Domain은 아무것도 모른다.
- PanelKit이 노출하는 인터페이스는 `show()/hide()/toggle()`과 상태 콜백뿐.
- 뷰모델은 Observation 프레임워크(`@Observable`), 비동기는 async/await.

## 5. 패널 인터랙션 (PanelKit)

- 화면 오른쪽 가장자리에서 슬라이드 인 (왼쪽 전환 가능). **[v1.1] 플로팅 형태** —
  상하·바깥쪽 12pt 여백 + 네 모서리 라운드("벽에 붙은 판"이 아니라 "떠 있는 종이").
  폭 기본 360pt, 설정에서 300~480pt 조절.
- `NSPanel` + `.nonactivatingPanel` + `becomesKeyOnlyIfNeeded` —
  패널이 떠도 현재 앱 포커스를 뺏지 않고, 입력 시에만 키를 가져간다.
- `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`, level `.floating` —
  풀스크린·모든 Spaces 위 표시.
- 글로벌 단축키 → 패널 열림 + 즉시 입력창 포커스. 재입력 또는 Esc → 닫힘 + 직전 앱 포커스 복귀.
- 열린 패널은 다른 앱 클릭에도 유지된다(참조하며 작업하는 패턴). 닫기는 Esc/단축키만.
- 메뉴바 아이콘: 좌클릭 토글, 우클릭 메뉴(설정·전체 내보내기·종료).

## 6. 데이터 모델과 저장소 (Domain + Data)

### Domain

- `Note` — 값 타입: `id: UUID`, `content: String`, `createdAt: Date`, `updatedAt: Date?`,
  **[v1.1]** `folderId: UUID?`(nil=미분류). 제목 없음. 정렬 기준 `createdAt`.
- **[v1.1]** `Folder` — 값 타입: `id: UUID`, `name: String`, `sortOrder: Int`, `createdAt: Date`.
- **[v1.1]** `FolderFilter` — `all / unfiled / folder(UUID)`. timeline·search가 이 필터를 받는다.
- 태그는 파생 데이터: 본문에서 추출하며 독립 엔티티가 아니다. 본문 수정 → 태그 자동 갱신.
- `HashtagParser` — 순수 함수. 한글·영문·숫자 허용, 공백/문장부호에서 종료.
- `HangulIndexer` — 순수 함수. 본문 → 자모열(`사이드`→`ㅅㅏㅇㅣㄷㅡ`) + 초성열(`ㅅㅇㄷ`).
- **[v1.2]** `ChecklistParser` — 순수 함수. 줄 단위 마커 인식(`ChecklistItem(lineRange/isChecked/text)`),
  괄호 안만 바꾸는 토글, (checked, total) 진행 계산. 저장 형식은 본문 그대로 — 스키마 무변경.
- `NoteRepository` protocol — `save / update / delete / timeline(paged) / search(query) / notes(tag:)`.

### Data (GRDB)

테이블 2개, 저장은 단일 트랜잭션으로 원자적 갱신:

- `note` — 본체 (**[v1.1]** `folder_id` nullable, folder 삭제 시 SET NULL)
- 검색 색인 — `note` 테이블의 `jamo`(자모 분해열)·`choseong`(초성열) 컬럼.
  부분 매칭에는 LIKE가 필요해 FTS 가상 테이블이 부적합하므로 컬럼 방식을 쓴다
- `note_tag` — `(note_id, tag)`, tag 인덱스
- **[v1.1]** `folder` — id/name/sort_order/created_at (마이그레이션 "v2")

스키마 버전 관리는 GRDB `DatabaseMigrator`. 저장소 구현체는 `DatabasePool` 위에서 async.

## 7. 검색

- `⌘F` → 입력창이 검색창으로 전환. Esc → 입력 모드 복귀. 별도 화면 없음.
- 타이핑 즉시 검색(150ms 디바운스), 타임라인이 결과로 필터링, 매치 쪽빛 하이라이트,
  결과 클릭 시 원래 타임라인 위치로 점프.

질의 3종 분류:

1. **전부 초성** (`ㅅㅇㄷ`) → 초성열 부분 매칭 (연속 부분 문자열 기준 — 건너뛰기 매칭 아님)
2. **한글 일반/조합 중** (`사이ㄷ`) → 질의·본문 모두 자모 분해 후 자모열 부분 매칭.
   조합 중에도 결과가 끊기지 않는 것이 핵심 요구사항
3. **영문/숫자** → 대소문자 무시 부분 매칭

`#태그` 포함 질의는 태그 필터 AND 텍스트 검색. **[v1.1]** 활성 폴더 필터와도 AND 결합.
정렬은 최신순 고정(랭킹 없음).
성능 전제: 개인 규모(수만 건)에서 밀리초 단위 — 1만 건 벤치마크 테스트로 검증.

## 8. 비주얼 — "한지에 붓"

- **테마 2종 모두 설계**: 라이트=한지(미색 + 은은한 섬유 질감 타일 에셋),
  다크=먹(짙은 회흑 바탕 + 옅은 미색 글자, 단순 반전 아님). 시스템 설정 자동 추종.
- **색**: 글자 먹빛(순검정 아님), 액센트 쪽빛(커서·하이라이트·링크).
  태그 색은 저채도 오방색 5색을 태그 이름 해시로 결정적 자동 배정.
- **타이포**: 본문 마루부리(전환 가능), UI 요소 Pretendard 고정 — 콘텐츠는 붓, 도구는 담백.
- **레이아웃**: 입력창 하단 고정, 메모 위로 쌓임, 날짜 구분선(오늘/어제/M월 D일).
  메모 = 떡메모지 낱장(바탕보다 한 톤 밝은 카드 + 미세 그림자). 모서리 불규칙화 같은 잔재주 금지.
- **모션** (전부 ≤200ms, 시스템 '동작 줄이기' 존중): 전송 시 낱장 안착, 패널 슬라이드 180ms ease-out.
  (글자 잉크 스밈 페이드인은 Task 14에서 NSTextView 오버레이로 시도했으나 빠른 타이핑 시
  이미 적용된 range가 뒤이은 삽입으로 밀려나며 엉뚱한 구간에 알파가 적용되는 문제가 있어 제외.)

  건드리지 않는다** — 한글 조합이 깨진다.

  구분선=실선, 불릿=•, 체크리스트=체크박스, 인용=좌측 괘선).

  **[QA r3] 체크박스는 커스텀 드로잉**: SF 심볼("배열같이 보인다" 피드백)이 아니라
  15pt 스트로크 1.5pt — 미완료 inkSoft 외곽선+투명, 완료 jjok 채움+백색 체크.
  **[QA r5] 모양은 원(Circle)** — 사용자 지시("`[ ]` 말고 그냥 동그라미로").
  저장 문법은 표준 `- [ ] `를 유지하고, 화면에 보이는 형태만 원이다.
  **[QA r3] 자동 성장 입력**: 컴포저·인라인 수정 필드는 내용 높이만큼 자란다
  (컴포저 44~160pt, 수정 필드 40~320pt, 초과 시 스크롤). 고정 클램프 금지.
  **[QA r3] 보내기 버튼 IME 규칙**: 전송 전 조합 중(marked) 텍스트를 반드시 확정하고
  draft를 동기화한 뒤 제출한다 — 조합 중 전송 시 글자 유실·잔여 텍스트 버그의 원인.
  ⑧ 설정 접근: 헤더 기어는 AppDelegate가 주입한 클로저로 연결.
  `NSApp.delegate as? AppDelegate` 캐스트 금지 — SwiftUI 수명주기에서는 내부 델리게이트가
  끼어들어 nil이 되며 버튼이 조용히 죽는다(v1.1 실제 버그).
  ⑨ 화면 모드: 설정 창 피커(시스템/밝게/어둡게) → `NSApp.appearance` 전역 적용.
- **절제 원칙**: 붓획 시뮬레이션·효과음 등 기믹 금지. 질감+먹빛+궁체+스밈 조합만으로.
- **디자인 우선 프로세스**: 이 앱의 핵심 품질 축은 기능이 아니라 미적 완성도다.
  SwiftUI 구현 전에 HTML 목업으로 한지 룩(색·질감·타이포·간격)을 확정하고,
  확정값을 디자인 토큰으로 추출해 SwiftUI로 옮긴다. 목업 반복이 네이티브 반복보다 빠르다.

## 9. 테스트 전략

- **Domain (주력)**: HashtagParser 엣지(연속 태그·문장부호·혼합·이모지),
  HangulIndexer(겹받침 `닭`, 복합 모음 `왜`, 초성 판별, 비한글 혼합), 질의 분류. TDD로 진행.

  마이그레이션, 1만 건 검색 벤치마크.

  (열림 시 입력 포커스 / Esc 후 직전 앱 복귀 / 풀스크린 위 표시 / 단축키 토글).
